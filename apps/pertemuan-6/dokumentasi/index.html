DOKUMENTASI · TASK MANAGER

Catatan Arsitektur & Teknis

Halaman ini isinya catatan soal keputusan desain, struktur kode, sistem gerak, dan perkakas yang kupakai di aplikasi Task Manager untuk Tugas PAW Pertemuan 6. Tiap bagian nunjuk langsung ke modul dan konfigurasi yang ada di repository.

Arsitektur Aplikasi & Mode Tampilan

Task Manager kubikin pakai Vanilla TypeScript dan DOM API bawaan, tanpa framework UI. Semua state ada di memori dan disinkronkan dari satu sumber data.

  • Mode Daftar (bawaan): Tugas ditampilkan dalam grid dua kolom di desktop/tablet dan satu kolom di layar sempit. .list-view punya gulir vertikal sendiri di dalam shell 100dvh, jadi header, bilah utilitas, dan footer selalu kelihatan.
  • Mode Orbital Stage: Aku bikin src/orbital-stage.ts untuk menata tugas secara spasial: satu kartu di tengah, dua sampai tiga kartu di busur ekuatorial, dan empat atau lebih tersebar di bola Fibonacci. Satu halaman orbital maksimal 12 kartu (ORBIT_LIMIT = 12) dengan paginasi. Bisa digeser pakai pointer (> 6px), diketuk (<= 6px), atau dikontrol panah keyboard, dan kartu yang difokus naik ke depan. Ada juga enam arketipe tipografi yang deterministik (src/archetypes.ts).
  • Pencarian & Filter Status: Filter Semua, Belum, dan Selesai jalan bareng pencarian real-time di judul, mata kuliah, kategori, dan deskripsi. Angka di tombol filter dan ringkasan footer selalu dihitung dari seluruh koleksi.
  • Dialog Detail & CRUD: Tambah, edit, konfirmasi hapus, dan baca detail (Reader Dialog dengan tombol Sebelumnya / Berikutnya dan Tutup ×) semuanya pakai elemen native <dialog>, dan fokusnya dikembalikan secara eksplisit.
  • Penyimpanan Lokal: Data disimpan di localStorage browser dengan kunci kxrumii:pertemuan-6:tasks:v1 (STORAGE_VERSION = 1), mode tampilan di kxrumii-task6-view-mode, dan tema di kxrumii:pertemuan-6:theme. Nggak ada backend, login, atau sinkronisasi antar perangkat.
Sistem Gerak, Tema & Transisi Rute

Semua animasi diatur di satu tempat, src/motion.ts, pakai Web Animations API (WAAPI) tanpa library animasi eksternal. Guard canAnimate() cuma mengizinkan animasi kalau prefers-reduced-motion: reduce nggak aktif, transisi rute lagi nggak jalan, dan browser mendukung Element.prototype.animate.

  • Kontinuitas Tampilan & Tata Letak: Rekonsiliasi DOM berdasarkan task.id (reconcileAccessibleList dan reconcileOrbitalStage) menjaga elemen tetap sama, jadi fokus checkbox nggak hilang dan baris nggak berkedip waktu mengetik di pencarian. Di Daftar ada FLIP reflow, di Orbital koordinatnya diinterpolasi halus, dan status pause manual (manualPaused) nggak ikut berubah.
  • Kontinuitas Kartu ↔ Reader: Waktu Reader dibuka, posisi kartu sumber di Daftar atau .box-print di Orbital diukur, lalu kliping relatifnya dihitung lewat computeViewportClipInset(). Waktu ditutup, #reader-dialog, .reader-bar, .reader-article, dan fade ::backdrop diselaraskan ke tugas yang sedang aktif (termasuk setelah pindah pakai Sebelumnya / Berikutnya), lalu semua animasi di tiap layer dibersihkan lewat clearReaderAnimations().
  • Penambahan Tugas & Accordion: Form tambah menutup #task-dialog sebelum render supaya reflow Orbital nggak ketahan, dan baris baru digulir ke area pandang Daftar kalau ada di luar viewport. Di halaman ini, src/accordion.ts menambahkan animasi tinggi WAAPI di atas <details> native, dan aman kalau diklik cepat berkali-kali.
  • Transisi Rute Dua Arah: Paket internal @kxrumii/transition-bridge (0.4.0) menyelaraskan transisi vertikal antara Task Manager (task-6), Dokumentasi (task-6-docs), dan Portal (portal). Ada juga sinkronisasi warna kanvas tema Gelap/Terang (src/theme.ts), fallback kalau storage diblokir, dan pembatalan animasi aktif saat event kxrumii:transition (exit-start) dikirim.

npm & Workspace Monorepo

Monorepo kxrumii.my.id pakai npm workspaces dengan Node.js 26.13.1 (engines.node >= 26.13.1) dan npm@12.2.3. packages/transition-bridge dan semua aplikasi tugas di apps/ terhubung di bawah satu package-lock.json di root.

  • Script workspace @kxrumii/pertemuan-6: dev, check (tsc --noEmit), test (node --test "tests/**/*.test.ts"), build (npm run check && vite build), dan preview.
  • Script root relevan: npm run dev:t6, npm run check, npm run build, npm run verify:transition, dan npm run preview.
  • Dependencies vs devDependencies: dependencies cuma berisi paket internal runtime @kxrumii/transition-bridge (0.4.0), sedangkan devDependencies berisi perkakas dev dan build (typescript ^7.0.2 dan vite ^8.3.8).
TypeScript

Semua kode sumbernya TypeScript mode strict dan dicek pakai tsc --noEmit sebelum di-bundle.

  • Interface & Union Types: Task, TaskDraft, TaskStatus, ViewMode, dan variasi arketipe pada src/types.ts; TaskFilter pada src/filters.ts; MotionGroup pada src/motion.ts.
  • Discriminated Union: Tipe Result<T, E> (ok: true | false) untuk hasil validasi input form pada src/validation.ts.
  • Generics: Helper updateById<T extends { id: number }> di src/tasks.ts dan requireElement<T extends Element> di src/render.ts.
  • Type Guards: isTask(value: unknown): value is Task di src/storage.ts serta isTaskFilter di src/filters.ts untuk memvalidasi data yang masuk.
Vite & Pipeline Build

Vite ^8.3.8 mengurus dev server lokal dan bundling produksi multi-halaman untuk Tugas 6.

  • Pengembangan lokal: npm run dev:t6 menjalankan Vite dev server dengan basis path /tugas/pertemuan-6/.
  • Konfigurasi multi-entry (vite.config.ts): Menentukan dua entry point (index.html dan dokumentasi/index.html), menyisipkan satu skrip bootstrap transisi rute v4 ke tiap dokumen aplikasi saat transform HTML, dan menulis output statisnya ke public/tugas/pertemuan-6/.
  • Integrasi monorepo Astro: Perintah root npm run build membersihkan artefak lama, membangun semua aplikasi Vite, lalu menjalankan astro build yang menyalin aset statis ke dist/tugas/pertemuan-6/, dan hasilnya dicek oleh scripts/verify-transition-bootstrap.mjs.
Environment Variables

Konfigurasi publik yang opsional dibaca lewat import.meta.env waktu build Vite jalan.

  • .env cuma ada di lokal dan diabaikan .gitignore. .env.example isinya template publik tanpa rahasia, jadi aman masuk Git.
  • Aplikasi membaca VITE_APP_NAME dan VITE_APP_VERSION. Nilai di build sekarang: nama Task Manager dan versi 1.0.0. Nilai bawaannya sama kalau file .env nggak ada (misalnya di CI).

Catatan keamanan klien. Semua variabel berawalan VITE_ disisipkan langsung ke bundle JavaScript di sisi klien, jadi siapa pun bisa membacanya di browser. Jangan taruh password, API key, atau secret apa pun di situ.

Compiler, Transpiler & Bundler
  • Compiler & Type Checker: tsc --noEmit mengecek semua kontrak tipe TypeScript tanpa menghasilkan file JavaScript.
  • Transpiler & Bundler: Menurut dokumentasi resmi Vite, Vite cuma mentranspilasi TypeScript dan nggak mengecek tipe. Makanya skrip build selalu menjalankan npm run check dulu sebelum vite build. Di Vite 8, Oxc yang mengubah TypeScript jadi JavaScript dan Rolldown yang menggabungkan modul serta aset statis.

Referensi resmi: Vite: Features dan Announcing Vite 8.
