DOKUMENTASI · TASK MANAGER

Catatan Arsitektur & Teknis

Halaman ini merangkum keputusan desain, arsitektur kode, sistem gerak, serta fondasi perkakas pada aplikasi Task Manager untuk Tugas PAW Pertemuan 6. Setiap bagian merujuk langsung ke modul dan konfigurasi yang ada di dalam repository.

Arsitektur Aplikasi & Mode Tampilan

Task Manager dibangun dengan Vanilla TypeScript dan native DOM API tanpa framework UI. Seluruh state berjalan di memori dan disinkronkan secara deterministik di atas satu sumber data tunggal.

  • Mode Daftar (bawaan): Menampilkan tugas dalam grid editorial dua kolom pada desktop/tablet dan satu kolom pada layar sempit. Kontainer .list-view mengelola gulir vertikal secara mandiri di dalam shell 100dvh sehingga header, bilah utilitas, dan footer selalu terlihat.
  • Mode Orbital Stage: Saya mengembangkan src/orbital-stage.ts untuk memproyeksikan koleksi tugas secara spasial: satu kartu terpusat, dua hingga tiga kartu pada busur ekuatorial, dan empat atau lebih pada proyeksi bola Fibonacci. Halaman orbital dibatasi maksimal 12 kartu (ORBIT_LIMIT = 12) dengan paginasi eksplisit, dukungan geser pointer (> 6px), ketuk (<= 6px), navigasi panah keyboard, elevasi fokus, serta enam arketipe tipografi deterministik (src/archetypes.ts).
  • Pencarian & Filter Status: Filter Semua, Belum, dan Selesai digabungkan dengan pencarian waktu nyata di seluruh judul, mata kuliah, kategori, dan deskripsi. Hitungan pada tombol filter dan ringkasan footer selalu mencerminkan seluruh koleksi.
  • Dialog Detail & CRUD: Penambahan, penyuntingan, penghapusan konfirmasional, dan pembacaan detail penuh (Reader Dialog dengan tombol Sebelumnya / Berikutnya serta kontrol Tutup ×) seluruhnya menggunakan elemen native <dialog> dengan pemulihan fokus eksplisit.
  • Persistensi Lokal: Penyimpanan memakai localStorage peramban pada kunci versi skema kxrumii:pertemuan-6:tasks:v1 (STORAGE_VERSION = 1), preferensi mode kxrumii-task6-view-mode, dan tema kxrumii:pertemuan-6:theme. Aplikasi ini tidak menggunakan backend, autentikasi, atau sinkronisasi lintas perangkat.
Sistem Gerak, Tema & Transisi Rute

Seluruh animasi antarmuka diatur terpusat oleh src/motion.ts memakai Web Animations API (WAAPI) tanpa pustaka animasi eksternal. Policy guard canAnimate() hanya mengizinkan animasi ketika prefers-reduced-motion: reduce tidak aktif, transisi rute tidak sedang berlangsung, dan browser mendukung Element.prototype.animate.

  • Kontinuitas Tampilan & Tata Letak: Rekonsiliasi DOM berbasis task.id (reconcileAccessibleList dan reconcileOrbitalStage) menjaga identitas elemen bertahan, menjaga fokus checkbox tetap utuh, menghilangkan flicker baris bertahan saat mengetik pencarian, serta menjalankan FLIP reflow di Daftar dan interpolasi koordinat halus di Orbital tanpa mengubah status pause manual pengguna (manualPaused).
  • Kontinuitas Kartu ↔ Reader: Pembukaan Reader mengukur posisi kartu sumber di Daftar atau .box-print di Orbital lalu menghitung kliping relatif melalui computeViewportClipInset(). Penutupan Reader menyelaraskan #reader-dialog, .reader-bar, .reader-article, dan fade ::backdrop ke tugas yang sedang aktif (termasuk setelah navigasi Sebelumnya / Berikutnya), lalu menyapu animasi pada seluruh layer melalui clearReaderAnimations().
  • Penambahan Tugas & Accordion: Penyerahan form tambah menutup #task-dialog sebelum render agar reflow Orbital tidak terblokir dan menggulir baris baru ke area pandang Daftar bila berada di luar viewport. Pada halaman ini, src/accordion.ts menambahkan animasi tinggi WAAPI yang responsif terhadap interupsi cepat di atas struktur native <details>.
  • Transisi Rute Dua Arah: Paket internal @kxrumii/transition-bridge (0.4.0) menyelaraskan transisi vertikal antara Task Manager (task-6), Dokumentasi (task-6-docs), dan Portal (portal), lengkap dengan sinkronisasi warna kanvas tema Gelap/Terang (src/theme.ts), fallback saat storage diblokir, serta pembatalan animasi aktif saat event kxrumii:transition (exit-start) dipancarkan.

npm & Workspace Monorepo

Monorepo kxrumii.my.id memakai npm workspaces pada Node.js 26.13.1 (engines.node >= 26.13.1) dan npm@12.2.3, menghubungkan packages/transition-bridge bersama seluruh aplikasi tugas di apps/ di bawah satu root package-lock.json.

  • Script workspace @kxrumii/pertemuan-6: dev, check (tsc --noEmit), test (node --test "tests/**/*.test.ts"), build (npm run check && vite build), dan preview.
  • Script root relevan: npm run dev:t6, npm run check, npm run build, npm run verify:transition, dan npm run preview.
  • Dependencies vs devDependencies: dependencies hanya memuat paket internal runtime @kxrumii/transition-bridge (0.4.0). devDependencies memuat perkakas pengembangan dan build (typescript ^7.0.2 dan vite ^8.3.8).
TypeScript

Seluruh kode sumber aplikasi ditulis dalam TypeScript mode strict dan diperiksa lewat tsc --noEmit sebelum proses bundling.

  • Interface & Union Types: Task, TaskDraft, TaskStatus, ViewMode, dan variasi arketipe pada src/types.ts; TaskFilter pada src/filters.ts; MotionGroup pada src/motion.ts.
  • Discriminated Union: Tipe Result<T, E> (ok: true | false) untuk hasil validasi input form pada src/validation.ts.
  • Generics: Helper updateById<T extends { id: number }> di src/tasks.ts dan requireElement<T extends Element> di src/render.ts.
  • Type Guards: isTask(value: unknown): value is Task di src/storage.ts serta isTaskFilter di src/filters.ts untuk validasi batas data.
Vite & Pipeline Build

Vite ^8.3.8 menangani server pengembangan lokal maupun bundling produksi multi-halaman untuk Tugas 6.

  • Pengembangan lokal: npm run dev:t6 menjalankan Vite dev server dengan basis path /tugas/pertemuan-6/.
  • Konfigurasi multi-entry (vite.config.ts): Menentukan dua entry point (index.html dan dokumentasi/index.html), menyuntikkan satu skrip bootstrap transisi rute v4 ke tiap dokumen aplikasi selama fase transform HTML, serta menuliskan output statis ke public/tugas/pertemuan-6/.
  • Integrasi monorepo Astro: Perintah root npm run build membersihkan artefak lama, membangun seluruh aplikasi Vite, lalu menjalankan astro build yang menyalin aset statis ke dist/tugas/pertemuan-6/ untuk diverifikasi oleh scripts/verify-transition-bootstrap.mjs.
Environment Variables

Konfigurasi publik yang bersifat opsional dibaca melalui import.meta.env saat build Vite berlangsung.

  • .env bersifat lokal dan diabaikan oleh .gitignore; .env.example menyimpan template publik non-rahasia yang aman dilacak oleh Git.
  • Aplikasi membaca VITE_APP_NAME dan VITE_APP_VERSION. Nilai aktif pada build saat ini adalah nama Task Manager dan versi 1.0.0, dengan nilai bawaan yang sama ketika file .env tidak tersedia (misalnya pada lingkungan CI).

Catatan keamanan klien. Seluruh variabel berawalan VITE_ disisipkan langsung ke dalam bundle JavaScript sisi klien dan dapat dibaca secara publik di browser. Tidak ada password, API key, atau secret yang boleh ditempatkan pada variabel tersebut.

Compiler, Transpiler & Bundler
  • Compiler & Type Checker: tsc --noEmit memverifikasi seluruh kontrak tipe TypeScript tanpa menghasilkan file output JavaScript.
  • Transpiler & Bundler: Menurut dokumentasi resmi Vite, Vite hanya melakukan transpilasi TypeScript dan tidak menjalankan pemeriksaan tipe. Oleh karena itu skrip build selalu menjalankan npm run check sebelum vite build. Pada Vite 8, toolchain Oxc menangani kompilasi/transformasi TypeScript ke JavaScript dan Rolldown menggabungkan modul serta aset statis.

Referensi resmi: Vite: Features dan Announcing Vite 8.
